## 可复用流程：大批量 UI 文案翻译

5088 个键直接翻译不可行，采用了「去重 + 分块 + 并行子代理」流程：

1. 用脚本扁平化 en.json，按**唯一值**去重（5088 键 → 4035 条唯一文案），记录每条的示例键路径作为消歧上下文（`ctx` = 三级前缀）。
2. 按字符量均衡切成 N 块（本次 10 块，每块约 350–490 条），写到临时目录，同时写 `<唯一值 -> id>` 映射表。
3. 派发等量子代理并行翻译，每个子代理把结果写成扁平 `{id: 中文}` JSON（要求分 2 个文件写，避免单次 Write 过长被截断）。共享一份 `INSTRUCTIONS.md` 统一术语表与硬约束。
4. 合并脚本按 en.json 层级还原，落盘前做四项断言：id 全覆盖、无占位符丢失、HTML 标签数量一致、扁平化后键集合与顺序完全一致。
5. 再做术语一致性抽检：统计 `模组/仪表板/模版` 等竞争译法的出现次数，确认未混入。

关键点：**去重后翻译**能把输入量降低约 20%，而按 id 回填天然保证同一文案处处一致；合并阶段的占位符/标签自动校验比事后人工抽查可靠得多。
